After you deploy an Anchor program, load the generated IDL, create a TypeScript client, read program accounts, and build transactions against Gorbagana RPC.

<Callout type="info" title="Use the package that matches your Anchor version">
  Current Anchor TypeScript docs use `@anchor-lang/core`. Older workspaces may still use `@coral-xyz/anchor`. Keep your imports, generated IDL types, and Solana client version aligned with the Anchor version in your workspace.
</Callout>

For full framework details, use the [official Anchor TypeScript client docs](https://www.anchor-lang.com/docs/clients/typescript). This page focuses on Gorbagana RPC, wallet signing, and explorer verification.

## Copy the IDL

Anchor writes the IDL artifacts when you build the workspace.

```bash
anchor build
```

Copy the generated files into your client app.

```bash
mkdir -p app/src/idl
cp target/idl/hello_gorbagana.json app/src/idl/hello_gorbagana.json
cp target/types/hello_gorbagana.ts app/src/idl/hello_gorbagana.ts
```

Replace `hello_gorbagana` with your program name. The JSON file describes the program interface. The TypeScript file gives the client typed access to that IDL.

## Create a read-only client

Use a connection-only `Program` when you only need to fetch accounts or build instructions.

```ts
import { Connection } from "@solana/web3.js";
import { Program } from "@anchor-lang/core";
import type { HelloGorbagana } from "./idl/hello_gorbagana";
import idl from "./idl/hello_gorbagana.json";

export const connection = new Connection(
  "https://rpc.gorbagana.wtf",
  "confirmed",
);

export const program = new Program(idl as HelloGorbagana, {
  connection,
});
```

This client does not have a default wallet. It is useful for reads and for building instructions that another wallet flow will sign.

## Read program accounts

Use the account namespace generated from your IDL.

```ts
import { PublicKey } from "@solana/web3.js";
import { program } from "./program";

const counterAddress = new PublicKey("COUNTER_ACCOUNT_ADDRESS");
const counter = await program.account.counter.fetch(counterAddress);

console.log(counter);
```

Replace `counter` with the account type from your program. Anchor derives the TypeScript account namespace from the IDL.

## Build an instruction

The `program.methods` builder follows the instruction and account names from your IDL.

```ts
import { Keypair, SystemProgram } from "@solana/web3.js";
import { program } from "./program";

const payer = Keypair.generate();
const counter = Keypair.generate();

const initializeInstruction = await program.methods
  .initialize()
  .accounts({
    payer: payer.publicKey,
    counter: counter.publicKey,
    systemProgram: SystemProgram.programId,
  })
  .instruction();
```

Replace `initialize`, the arguments, and the account names with the method generated from your program. Use `.instruction()` when you want to add the instruction to your own transaction flow.

## Send from a script

For local scripts, load a funded keypair and send a transaction through Gorbagana RPC.

```ts
import {
  Keypair,
  SystemProgram,
  Transaction,
  sendAndConfirmTransaction,
} from "@solana/web3.js";
import fs from "node:fs";
import { connection, program } from "./program";

function loadKeypair(path: string) {
  const secret = JSON.parse(fs.readFileSync(path, "utf8")) as number[];
  return Keypair.fromSecretKey(Uint8Array.from(secret));
}

const payer = loadKeypair(process.env.GOR_KEYPAIR_PATH!);
const counter = Keypair.generate();

const initializeInstruction = await program.methods
  .initialize()
  .accounts({
    payer: payer.publicKey,
    counter: counter.publicKey,
    systemProgram: SystemProgram.programId,
  })
  .instruction();

const transaction = new Transaction().add(initializeInstruction);

const signature = await sendAndConfirmTransaction(
  connection,
  transaction,
  [payer, counter],
);

console.log(`https://explorer.gorbagana.wtf/tx/${signature}`);
```

Fund the payer with native GOR before running the script. If your instruction creates a new account, include that account keypair in the signer list.

## Send from a browser wallet

In React, use the wallet adapter connection and Anchor wallet object to create a provider. Backpack should sign the transaction in the browser.

```tsx
"use client";

import { AnchorProvider, Program, setProvider } from "@anchor-lang/core";
import { useAnchorWallet, useConnection } from "@solana/wallet-adapter-react";
import { useMemo } from "react";
import type { HelloGorbagana } from "@/idl/hello_gorbagana";
import idl from "@/idl/hello_gorbagana.json";

export function useAnchorProgram() {
  const { connection } = useConnection();
  const wallet = useAnchorWallet();

  return useMemo(() => {
    if (!wallet) return null;

    const provider = new AnchorProvider(connection, wallet, {
      commitment: "confirmed",
    });

    setProvider(provider);

    return new Program(idl as HelloGorbagana, {
      connection,
    });
  }, [connection, wallet]);
}
```

Use `.instruction()` or `.transaction()` when your app has its own signing and confirmation flow. Use `.rpc()` only when the provider has a wallet and you want Anchor to build, sign, and send the transaction for you.

## Confirm in the explorer

Always surface the transaction signature after a write.

```ts
export function explorerTxUrl(signature: string) {
  return `https://explorer.gorbagana.wtf/tx/${signature}`;
}
```

Open the explorer link and check the status, fee payer, invoked program, logs, and account changes.

## Common issues

<Accordions type="single">
<Accordion title="The IDL address does not match the deployed program">

Check the Program ID in the IDL and compare it with the deployed program.

```bash
solana program show PROGRAM_ID \
  --url https://rpc.gorbagana.wtf
```

If the IDL was copied from an older build, rebuild the Anchor workspace and copy the fresh files from `target/idl` and `target/types`.

</Accordion>

<Accordion title="The client has no wallet">

A connection-only `Program` can fetch accounts and build instructions, but it cannot sign transactions. Use a browser wallet provider for frontend writes or a local keypair for scripts.

</Accordion>

<Accordion title="The wallet adapter object is not accepted by Anchor">

Use `useAnchorWallet()` for Anchor provider setup. The generic `useWallet()` hook exposes more wallet state, but Anchor needs the wallet shape used by `AnchorProvider`.

</Accordion>

<Accordion title="The account names do not typecheck">

Account names come from the IDL. Run `anchor build`, copy the latest `target/types/PROGRAM_NAME.ts`, and update the `.accounts({ ... })` object to match your program instruction.

</Accordion>

<Accordion title="The transaction succeeds but the app does not show the new state">

Wait for confirmation, then refetch the account using the same connection commitment. If the account was created in the transaction, fetch the new account address, not the Program ID.

</Accordion>
</Accordions>
