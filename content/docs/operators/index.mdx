This section is for teams running dedicated Gorbagana infrastructure.

Start with an RPC node if you need dedicated application infrastructure. Run a consensus validator only if you are ready to operate a voting node, manage validator keys, monitor uptime, and fund ongoing vote transactions.

## Choose what to run

**RPC node**

- Serves JSON-RPC and WebSocket traffic for apps, scripts, indexers, and explorers.
- Usually runs with voting disabled.
- Needs rate limits and request filtering if you expose it publicly.
- Start here if you need dedicated infrastructure for an app or service.

**Consensus validator**

- Replays the ledger and participates in consensus.
- Uses a vote account and validator identity.
- Needs native GOR for vote transaction fees.
- Needs monitoring, security procedures, and stake delegation.

## Recommended path

1. Use the public RPC endpoint while you build.
2. Run your own RPC node when your app needs dedicated throughput, custom retention, or an isolated endpoint.
3. Run a validator only after you have a funded operator wallet, a monitored host, and a key-management plan.
