Use Solana knowledge as the starting point for Gorbagana development. The account model, transaction model, program model, RPC shape, and deployment tooling stay familiar; network values, native token assumptions, explorer links, wallet guidance, and bridge flow change.

## Compatibility map

Use this table when you are moving a Solana app, script, or deployment process to Gorbagana.

| Surface | Carries over | Change for Gorbagana |
| --- | --- | --- |
| Accounts | Wallet accounts, program accounts, program-owned state, owners, rent/account allocation concepts | Fund accounts with native GOR |
| Transactions | Signatures, recent blockhashes, instructions, account metas, atomic execution | Show GOR amounts and Gorbagana explorer links |
| Programs | SBF artifacts, Program ID, ProgramData, upgrade authority, PDAs, CPIs | Deploy to `https://rpc.gorbagana.wtf` |
| RPC | Solana JSON-RPC shape, commitments, WebSocket subscriptions, client libraries | Use Gorbagana HTTP and WebSocket endpoints |
| Wallets | Solana-style addresses and wallet signing flows | Backpack is the documented wallet path |
| Tokens | 9-decimal native token unit model | Native token is GOR, not SOL |
| Bridge | Solana token transfer concepts | Bridge between Solana GOR token and native GOR |

## What works the same

Gorbagana follows the SVM development model, so most Solana concepts still apply.

## Configure tools

Point Solana-compatible tools at Gorbagana before running balances, transfers, or deployments.

<Tabs items={["CLI", "TypeScript"]}>
<Tab>

```bash
solana config set --url https://rpc.gorbagana.wtf
solana config get
solana balance
```

</Tab>
<Tab>

```ts
import { Connection } from "@solana/web3.js";

export const connection = new Connection(
  "https://rpc.gorbagana.wtf",
  "confirmed",
);
```

</Tab>
</Tabs>

Some library constants and CLI help text keep Solana names. For example, `LAMPORTS_PER_SOL` is still the base-unit constant from `@solana/web3.js`; when your client points at Gorbagana, treat that value as base units per `1 GOR`.

```ts
import { LAMPORTS_PER_SOL } from "@solana/web3.js";

export function formatGor(baseUnits: number) {
  return baseUnits / LAMPORTS_PER_SOL;
}
```

## Programs and deployment

Solana program deployment docs are useful for loader behavior, SBF builds, ProgramData, and upgrade authority. Use Gorbagana docs for network values and deployment examples.

<Steps>
<Step>

### Build the program

Build SBF artifacts with the same Solana-compatible toolchain.

```bash
cargo build-sbf
```

</Step>
<Step>

### Deploy to Gorbagana

Deploy the compiled `.so` to Gorbagana RPC.

```bash
solana program deploy ./target/deploy/PROGRAM.so \
  --url https://rpc.gorbagana.wtf
```

</Step>
<Step>

### Inspect the program

Check ProgramData, authority, size, balance, and last deployed slot.

```bash
solana program show PROGRAM_ID \
  --url https://rpc.gorbagana.wtf
```

</Step>
</Steps>

For Anchor projects, keep `Anchor.toml`, `declare_id!`, and generated keypairs aligned with the Program ID.

## Wallets and funding

Wallet flows still use Solana-style addresses and signatures. The documented wallet path is Backpack.

Browser apps should show the network, sender, recipient, amount, and fee payer before asking a wallet to sign. Scripts should use local keypairs only on machines you control.

## Bridge and token flow

GOR has two surfaces:

| Direction | Source asset | Destination asset | Use |
| --- | --- | --- | --- |
| Solana to Gorbagana | GOR token on Solana | Native GOR on Gorbagana | Fund wallets, apps, and deployments |
| Gorbagana to Solana | Native GOR on Gorbagana | GOR token on Solana | Move back to the Solana token |

Always verify the destination address before signing. After bridging, search the destination address or transaction signature in the explorer before retrying.

## When to use Solana docs

Use Solana docs for general SVM concepts and tooling behavior. Use Gorbagana docs when a value, URL, token, wallet, or bridge direction depends on this network.

| Use Solana docs for | Use Gorbagana docs for |
| --- | --- |
| Accounts, instructions, transactions, PDAs, CPIs | RPC, WebSocket, explorer, bridge, and token values |
| SBF program structure and loader concepts | Deploy commands already pointed at Gorbagana |
| Anchor framework concepts and account constraints | Backpack setup and Gorbagana-specific frontend examples |
| JSON-RPC method behavior | Public endpoint, rate expectations, and explorer links |

Useful upstream references:

- [Solana docs](https://solana.com/docs)

- [Solana JSON-RPC](https://solana.com/docs/rpc)
- [Anchor docs](https://www.anchor-lang.com/docs)

## Migration checklist

Use this checklist when you port a Solana app, script, or deployment flow.

- Replace RPC and WebSocket URLs with Gorbagana endpoints.
- Fund the payer with native GOR.
- Show GOR amounts with 9 decimals in app UI.
- Replace Solana explorer URLs with Gorbagana explorer URLs.
- Use Backpack for wallet flows documented here.
- Check Program IDs and upgrade authorities before deployment.
- Search signatures in the explorer after every deploy or transfer.
- Remove devnet, testnet, faucet, and SOL assumptions unless a Gorbagana page documents them.
