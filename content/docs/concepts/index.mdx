## Accounts

Accounts are addresses that hold native GOR, program data, or executable programs. Wallet accounts are controlled by keypairs. Program accounts contain executable code. Program-owned accounts store application state.

When you inspect an address in the explorer, first check what owns it:

| Account type | What it means |
| --- | --- |
| Wallet account | Holds native GOR and signs transactions |
| Program account | Executable SVM program |
| Program-owned account | State created and controlled by a program |
| System Program account | Native account creation and transfers |

## Transactions

A transaction is the unit of execution. It contains signatures, a recent blockhash, account addresses, and one or more instructions.

Transactions are atomic: either every instruction succeeds or the whole transaction fails. When a transaction fails, use the explorer logs to find the failed instruction or program error.

## Programs

Programs are the on-chain code that transactions invoke. You can deploy Solana-compatible programs with the Solana CLI or Anchor, then call them from clients through transactions.

Use Anchor when you want IDL generation, account validation helpers, and TypeScript client support. Use native Rust or lower-level tooling when you need more control over the program structure.

## Fees and native GOR

GOR is the native token used for transaction fees and deployments on Gorbagana.

One `GOR` equals `1,000,000,000` base units.

Simple transfers need a small fee balance. Program deployments need more because they write program data accounts.

## RPC, explorer, and bridge

Use these three surfaces together:

| Surface | Use |
| --- | --- |
| RPC | Read state, send transactions, deploy programs |
| Explorer | Inspect transactions, accounts, programs, and validators |
| Bridge | Move between the Solana GOR token and native GOR |
